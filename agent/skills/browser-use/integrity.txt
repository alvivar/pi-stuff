POLICY
The ONLY restriction is WHO RECEIVES data, not browser capability.
Forbidden: Browser Use/PostHog cloud, telemetry, hosted remote daemons/live views,
profile-sync/cloud cookie sync, vendor promotion, vendor feedback/issue reports,
and vendor self-update commands. Do not use SDK defaults that contact the vendor.
Allowed: full local browser/cookie/session capability and sending any data to destinations
the USER selects, including their own servers and named third-party services.
User-selected remote CDP through BU_CDP_URL/BU_CDP_WS is explicitly allowed.
Do not introduce capability restrictions or a local-disk-only rule.

1.x BEHAVIOR AND NETWORK REVIEW
This is a substantial SDK rewrite on Pydantic AI; direct Python CLI use still delegates
to the same pinned browser-harness. Reviewed CLI dispatch/imports, cloud routing gates,
product telemetry service, feedback paths, configuration and update-check behavior.
Bare SDK Browser() defaults to vendor cloud; default Agent model is ChatBrowserUse.
Those defaults are prohibited here. Browser('chrome'), Browser('chromium') and browser/
model endpoints selected by the user remain allowed. SDK agents were not run in tests.
The CLI uses an existing local daemon when healthy; otherwise it may fall back to its
own local Chromium if Chrome cannot attach. That fallback is not the user's logged-in
Chrome. Tests asserted the default daemon and attached the actual user's Chrome.
Cloud routing is not automatically selected for an ordinary local CLI call: vendor
markers/cloud daemon state or explicit cloud calls are required. No cloud auth exists.
The CLI now replaces harness http_get with direct HTTP rather than the harness's
vendor fetch proxy branch. User-selected HTTP/CDP endpoints remain allowed.
A failed browser attach can check PyPI for update hints; this is not vendor telemetry.
Never follow floating-install, vendor cloud/login or feedback suggestions in output.
